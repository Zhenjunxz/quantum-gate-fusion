# Mac 首次性能试跑记录（2026-11-12）

本目录来自一位小组成员提交的 `results.zip`，保留原始计时数据、程序汇总结果及运行环境。**这些是一次探索性运行，不是小组最终结论**。该次试跑对应程序 `benchmark.py --ns 12 14 16 18 20 22 --repeats 15`。

## 已保存的材料

- `raw_timings.csv` — 180 条原始记录：6 个 qubit 规模 × Baseline/Fusion × 每种实现 15 次；包含执行顺序、纳秒和毫秒。
- `summary.csv` — 每个规模的中位运行时间、加速比、算法层面逻辑字节数及最大绝对输出误差。
- `environment.json` — 实际环境：Python 3.13.9（Anaconda 构建）、NumPy 2.5.4、Numba 0.68.1、Apple Silicon / arm64、macOS 26.6.2；随机种子 42。文件只记录通用的 CPU 架构 `arm`，**未记录具体芯片型号**，正式复现实验需要补充。
- `runtime.svg` — 根据 `summary.csv` 中位数生成的折线图，可直接在 GitHub 预览。用户本机原始 `runtime.png` 可以通过基准脚本重建；若需要精确保存原始 PNG，请单独上传。

## 结果（单位：ms；重复 15 次的中位数）

| qubits | Baseline | Fusion | Speedup |
|:---:|---:|---:|---:|
| 12 | 0.009333 | 0.006584 | 1.4175× |
| 14 | 0.037667 | 0.026000 | 1.4487× |
| 16 | 0.137542 | 0.094208 | 1.4600× |
| 18 | 0.552666 | 0.374083 | 1.4774× |
| 20 | 2.240625 | 1.510708 | 1.4832× |
| 22 | 9.226833 | 5.987459 | 1.5410× |

所有六个规模的 Fusion 时间中位数低于 Baseline，最大加速比为 1.54×（n=22）。这不是其他 CPU 上的性能承诺。

### 数据检查和解读限制

1. `summary.csv` 的中位数与 `raw_timings.csv` 可以交叉核对；原始结果保留了时间抖动。例如 `n=14` 的第 8 次 Fusion 为 **0.066791 ms**，相较中位数 **0.026000 ms** 明显偏慢，不应删去或悄悄修正。
2. 状态数组从 64 KiB（12 qubits）增长至 64 MiB（22 qubits）；观察到的加速比总体升高，但只有六个规模，不能证明单调规律。
3. 两个内核执行等价数学任务。Baseline 需要两次遍历，Fusion 一次遍历，理论逻辑读写量减半；**不等于实测 DRAM 字节流量或 Cache Miss 减半**。
4. 该 benchmark 的 `state.copy()` 在计时区间外，但会预热缓存；Cache 热态可能影响结果。Numba/编译器生成的指令不同也可能影响耗时。
5. 时间为单次内核执行时间，未包含状态初始化、复制及首次 JIT 编译，不代表端到端量子线路模拟性能。
6. 每种方法目前只有 15 次重复的单轮结果；正式结论应补充独立重跑、多组实验以及对 CPU 具体型号/软件环境的记录。

## 如何独立复现

从仓库根目录执行：

```bash
python -m pytest -q
python benchmark.py --ns 12 14 16 18 20 22 --repeats 15 --output results
```

此命令会产生你**自己机器上**的新数据，不能保证与本次运行相同。仓库根目录的 `results/` 默认被 `.gitignore` 忽略，避免意外覆盖本目录归档。实验过程中不要把不同机器的绝对运行时间直接合并为一组。

小组讨论与其他成员的验证结果见 [Issue #1](https://github.com/Zhenjunxz/quantum-gate-fusion/issues/1)。
